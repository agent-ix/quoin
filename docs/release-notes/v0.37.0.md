# Quoin v0.37.0

Quoin v0.37.0 updates its default modules and engine, and expands validation
and dossier evidence handling.

## Highlights

- Default modules advance to Engineering Assurance `v0.11.0`,
  spec-artifacts-iso `v0.28.0`, spec-artifacts-process `v0.38.0`,
  spec-objects-business `v0.11.0`, spec-objects-architecture `v0.15.0`,
  spec-objects-operational `v0.11.0`, spec-objects-security `v0.19.0`, and
  spec-objects-safety `v0.9.0`.
- Quire engine and fixture dependencies advance to `v0.63.1`, including the
  PLAT-1856/PLAT-1852 relation fixes and cross-module reference resolution.
- Validation reports can be generated from retained evidence, preserve valid
  supplier records, and report known anomalies against the producer version.
- Process-risk and intended-use records are retained with ratings marked as
  proposed until human acceptance.
- `quoin validation ratings --coverage` reports feature-rating and self-test
  trace coverage, including invalid markers and uncovered high-risk features.

## Known limitations

- The per-feature coverage rule implemented by `quoin validation ratings
  --coverage` is being replaced. Treat its current high-risk coverage result
  as provisional; the replacement rule is not included in this release.
- Validation report completeness depends on the retained evidence supplied by
  the run. Quire-side anomaly embedding remains separate follow-up work.
- FR-193-AC-10/11 remain unmet on the real Quoin host path. With the
  `plat-1856.json` module fixture from quire-rs `v0.63.1`, the candidate's
  `quoin matrix --repo <repo> --module <module> --no-project-config --json`
  exits 2 with empty stdout and `CORE_REFUSED` / `QQ-1022` for the dropped
  `connection-carries-classification` relation; no valid sibling matrix entry
  is returned. Released Quoin `0.36.10` also cannot process the fixture's
  required-relations model and exits 2 with `QQ-1020` (no traceability model),
  so it does not establish a passing baseline. The follow-up is
  [PLAT-1904](https://linear.app/agent-ix/issue/PLAT-1904/quoin-matrix-drops-valid-output-when-a-required-relation-fails-to-load).
  FR-193 remains unchanged and unmet until the real host path returns valid
  entries together with dropped-relation diagnostics.
- Existing Quoin module management has known limitations: `module
  ensure-defaults` can leave stale module refs; `IX_CONFIG_ROOT` is ignored by
  `module ensure-defaults` and `module list` (use `--config-root`); registry
  paths are absolute; SOUP promotion omits SBOM supplier/license values; the
  ISO FR skeleton and manifest disagree about `Dependencies`; and dossier
  generation/export needs a separate `--module` for each module root.
