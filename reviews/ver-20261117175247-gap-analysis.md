## Scope

- FR-209-AC-1 (examined): Given a `quire.flow-report/v1` report with `denials: []`, `dataflow_rules_pass` passes; given any report with one or more denials, it fails as `dataflow_denied`, including when the denial severity is `warning` and the evaluator exits 0.
- FR-209-AC-2 (examined): A seeded connection carrying a classification with `regulated_categories: [health]` across an `untrusted` boundary, with no protecting `encrypt-in-transit` control, produces a denial. The scripted agent receives the denial's rule, subject, matched classification and boundary, data category `health`, and `encrypt-in-transit` remediation name, description, and change. After the agent proposes the corresponding control, the next report has no denials and the run reaches `passed`.
- FR-209-AC-3 (examined): A report with the wrong schema identifier, malformed JSON, missing `denials`, missing `matched` data, an unavailable evaluator, or a nonzero evaluator failure without a usable report fails as `dataflow_check_unavailable`; none reaches `passed` or is treated as a design denial.
- FR-209-AC-4 (examined): A scripted proposer write targeting `required_relations`, `traceability.flow_rules`, or declared rule data is rejected before application with `rules_modified`; the run never reaches `passed`, and the workflow creates no run-start snapshot, path/content record, or file diff for this guard.
- FR-209-AC-5 (examined): A scripted agent that never resolves a denial receives four evaluator checks total: the initial proposal and three retries. After the fourth failed check the run reaches `escalated`, with no fifth agent retry. A scripted agent that resolves the denial on its fourth check reaches `passed`.
- FR-209-AC-6 (examined): The workflow definition has exactly the phases and transitions in Behavior; every transition into `accepted` or `rejected` is gated by `hitl`, and neither terminal phase has an outgoing transition.
- FR-209-AC-7 (examined): The agent cannot acknowledge a HITL gate or transition the workflow into either terminal phase. A run with no human acknowledgement remains at its prior phase.
- FR-209-AC-8 (examined): A person accepting an escalated run leaves its valid denials in the retained report and the run output states both `accepted` for the human decision and `dataflow_denied` for the evaluator result; it does not state that the evaluator passed.
- FR-209-AC-9 (examined): Running the scripted workflow tests creates no signature, signed commit, signer configuration, allowed-signers file, signing key, or release/tag configuration. The workflow and tests do not invoke signed-record verification.
- FR-209-AC-10 (examined): If the scripted design agent cannot start or returns no usable edit, the run stops in its current `proposing` or `revising` phase with `design_agent_unavailable`; it does not create a denial, consume a retry, or reach `passed`, `escalated`, `accepted`, or `rejected`. An operator can resume or end the run.
