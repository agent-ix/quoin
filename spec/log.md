* **2026-08-19** — **CR-020**: new [FR-041](./functional/FR-041-sbom-inventory-evidence.md) — **SBOM inventories as run evidence** (agent-ix/quoin#116). The catalog declared `sca-sbom` and nothing could discharge it.

  **The deferral was the point, and it paid.** This ticket sat unstarted through Wave C with an explicit trigger: *"quoin#94 is the ticket that answers this, because it is the first consumer that has to render the claim. Building the intake before the consumer exists is how a record type gets a shape nothing needs."* FR-040 landed, and its answer is legible in what it renders — a GSN evidence leaf is **one line per obligation**, and renders no component list. So the claim an SBOM supports is *"a complete inventory was produced at this commit"*: a run record. Contents-level judgement already lands through `cargo-audit` and SARIF. **No third record type**, which is exactly what the deferral was protecting.

  **One entry per component, and the reason is vacuity.** The obvious alternative — a single entry carrying the count in `score` — is wrong in an instructive way: an SBOM listing nothing would be indistinguishable from a healthy one without a new check. As entries, an empty inventory produces zero entries and `vacuous-evidence` names it with no new machinery. Model the thing so the existing checks apply, rather than summarise it and re-derive what the summary lost.

  Identity is the **purl**, from wherever the format keeps it — CycloneDX at the component, SPDX in `externalRefs[referenceType = purl]`. Reading `name` would give one component two identities depending on which tool produced the document. A component carrying neither is **dropped, not given one**: a fabricated symbol binds to nothing *and* inflates the count that proves the inventory is non-empty, making an unreadable SBOM look healthier than an empty one. A document that is neither format is **refused**, because zero entries is a real finding about the consumer's build and an unreadable file must not masquerade as one.

  Both fixtures are real tool output, unedited: `@cyclonedx/cyclonedx-npm` 6.0.1 over an actual `npm install`, and GitHub's dependency-graph SPDX for `sindresorhus/slugify`. TC-231..TC-236.

  This closes the adapter family opened by agent-ix/quoin#91, and with it the last outstanding item of ADR-0011 Phase 2.


* **2026-08-19** — **CR-019**: new [FR-040](./functional/FR-040-assurance-case-view.md) — the **assurance-case view**, `quoin assurance` (agent-ix/quoin#94, Wave E). A pile of green evidence is not an argument: a matrix of ✅ says every row has something attached, not why the thing anyone cares about is true. ISO 15026-2 / GSN is the shape that does, and this renders it from data the program already holds — the trace graph, quire's obligations, and the auditor's verdict on each binding.

  **Gaps are nodes, not omissions**, which is the whole reason to build it and the reason to build it carefully. An undischarged obligation, a suspect binding, a claim nothing traces to: each stays in the tree as an open node carrying the auditor's reason verbatim. A case narrowed to only what it can prove is indistinguishable, to a reader, from a complete one — and an assurance case is the single most tempting artefact in the system to narrow, because the narrowed version looks better and nothing anywhere would object.

  **That section earned itself on the first run.** Over this repository it reported **15 requirements reachable from no claim**. Seven had been added during this program — FR-034, FR-035, FR-036, FR-037, FR-039, NFR-011, NFR-012, none of which carried an upward edge — and are traced in this change. The other eight are NFR-001..NFR-009 minus NFR-004, which predate it and each need a judgement about which stakeholder requirement they serve; filed as agent-ix/quoin#136 rather than guessed at, since a wrong edge is worse than a missing one because it makes the case *look* argued.

  Three smaller decisions. The **auditor's verdict** decides whether a leaf is supported; re-deriving freshness here would be a second answer to a question FR-032 already answers. The decomposition is read **in the direction the corpus writes it** — a child declares `traces_to`, never a parent declaring its children — and an obligation's owner comes from its **id**, because obligations are minted from a document's own tables and an edge for that would be another thing to keep in agreement. The **claim type is a parameter**: a safety bundle argues from a declared hazard and a security bundle from a threat, and a built-in `StR` would make the view useless to exactly the bundles that need an assurance case most.

  The bundle reader FR-037 introduced is **generalized and shared** rather than copied, because no quire surface exposes the bundle graph as data and two readers over the same files drift — the second written by whoever needs a field the first does not expose. agent-ix/quire-rs#179 is where that stops being necessary. TC-221..TC-230.


* **2026-08-19** — **CR-018**: new [FR-039](./functional/FR-039-mutation-score-threshold.md) — **mutation score as a declared verification threshold** (agent-ix/quoin#48). Every quality signal this program has built over acceptance criteria is a proxy — vague verb, concrete object, assertion shape — and those are word lists over an open vocabulary. The corpus already showed what that is worth: **1,201 distinct verb stems, of which a built-in list of 13 covered 14.5%**. A mutation score is the direct answer to the question they approximate: does the test discriminate the behaviour the criterion describes?

  Half the work had shipped in Wave C and was never wired to anything — the `cargo-mutants` adapter records the score and `RunEntry.score` exists to hold it, while `grep -n mutation src/auditor/` returned **one comment and no check**. All four blockers this ticket recorded in Phase D1 are closed.

  **The floor is declared, never assumed.** `--mutation-floor <criticality>=<ratio>` is unset by default, for the reason CR-008 deleted the hardcoded `multiplicityRequires: ["P0"]`: 2,304 of 2,304 `Acceptance Criteria` tables in the ecosystem carry no priority column, so a built-in floor is a rule nobody chose that fires on everything the moment one appears.

  **Two findings, because the failures differ.** `insufficient-mutation-score` — the tests ran and did not discriminate. `unmeasured-mutation-score` — a floor is demanded and nothing records a score, which is **not** `undischarged`: the obligation may be thoroughly tested, with a passing bound run, and still have nothing saying the tests detect anything. A threshold that cannot be evaluated is not a threshold met, and folding it into the undischarged bucket would hide it behind evidence that already exists.

  Three smaller decisions, each with a failure it prevents. The judgement is on the **worst** bound symbol, not the mean, because averaging lets a well-tested symbol carry one whose mutants all survive. A **skipped** symbol's absent score is not read as zero, which would fail an obligation for a test nobody ran. And `--mutation-floor P0=80` is **refused**: it is the natural thing to type, it is a floor nothing can reach, and accepting it silently reports every `P0` as failing in a form indistinguishable from a real finding. A malformed pair is refused for the same reason — an ignored floor reads as a passing gate.

  **TC-219 and TC-220 first landed unbacked.** Written as `describe("TC-219 …")`, they reconciled to nothing: `quire coverage` reported both as unbacked rows AND status lies, which is agent-ix/quoin#124 reproduced by hand while writing the fix for something else. The tags moved onto the `it()` symbols and both bind. Worth recording that the matrix said ✅ the whole time.


* **2026-08-19** — **CR-017**: new [FR-038](./functional/FR-038-generate-fuzz-harnesses.md) and [US-012](./usecase/US-012-generate-fuzz-harnesses.md) — the **`spec-fuzz` skill** (agent-ix/quoin#93). Robustness requirements are property-shaped over an input surface, and `spec-correctness` generates example and property tests, not fuzz targets. Between the catalog recommending `fuzzing` and a running fuzzer there was nothing.

  **No new declaration.** The catalog already carries two Fuzz-kind methods and FR-031's advisor already reaches the first from `untrusted-input` and `parser`. A "fuzzable surface" manifest key would be a third source of truth about the same fact, disagreeing with the catalog the first time either changed. The selector is `evidence_kind: Fuzz`, read at run time — and TC-EV-054's fixture **renames the method** to `robustness-search`, so a skill matching on the name `fuzzing` passes every other assertion and fails only there.

  **A harness names a symbol or it is not written.** A property test that grounds nothing is a weak test; a fuzz target that calls nothing is a build error in a harness most reviewers never run locally. Ungrounded produces a finding naming what was looked for, and no file.

  **Absent tooling is a finding, never an install.** A fuzz workspace is a dev-dependency, a nightly toolchain and a CI job, and adding all three to somebody's repository because their spec mentioned a parser is a decision that belongs to them (ADR-0011: generated artifacts are consumer-owned).

  **Writing a target discharges nothing**, which is where this differs from every other generator in the family. A property test that exists and passes is evidence; a fuzz target that exists has proved nothing, because fuzzing is a search and an unrun target is a search never started — while looking, in every report and matrix, exactly like coverage. Discharge is a recorded run in a suite with `Evidence Kind: Fuzz`.

  **The evals were run, not asserted.** TC-EV-054 failed on the first live run: the agent had emitted a correct target at `test/codes.fuzz.test.js` and the scenario's glob was `**/*fuzz*.{js,ts,mjs}`. `evals/lib/assert.mjs`'s `globToRegExp` **escapes `{` and `}`**, so brace expansion is not supported and that glob matches a literal suffix. `fileContains` failed loudly, which is how it was found — but the same glob in `absentFiles` would have **passed vacuously**, an assertion written to prove a file was not created passing whether or not it was. Filed as agent-ix/quoin#135; no scenario on `main` used one. TC-EV-054 passes 1/1 after the fix.

  The dogfood target is real: `quire-rs`'s nine fuzz targets reach `parse_document`, `extract`, `corpus::walk`, `loader::*` and `apply_patch`, and **nothing** reaches `symbols/`, `grammar/`, `coverage.rs` — nor `combinatorial`, `obligation`, `query`, `vocab` or `traceability`, all added by this program. TC-EV-054..TC-EV-057.

* **2026-08-18** — **CR-015**: new [FR-037](./functional/FR-037-declared-vocabulary-completeness.md) — **declared-vocabulary completeness and its verdict policy**, and the `quoin completeness` command (agent-ix/quoin#81). Coverage answers *"is every criterion tested?"* and cannot answer *"is anything missing?"*, because a requirement nobody wrote has no criterion to be uncovered. quire-rs FR-059 answers the second question; ADR-0011 leaves the verdict here, citing the FR-050 precedent by name.

  **The vocabulary is read, never minted.** ISO 25010 is the first instance and its characteristic list is module data — **12** values in `spec-artifacts-iso`'s NFR frontmatter schema, where the ticket had proposed walking a hardcoded 9. Nothing in this is 25010-specific: test-type coverage over a Test Matrix, STRIDE coverage over declared threats and `escape_cause` coverage over Findings are the same shape and already visible in module data.

  **A justified absence is an answer, and today it costs nothing.** Measured on this repository: `quire validate --okf` reported **7** unowned characteristics; adding one frontmatter line — `quality_attributes_not_applicable: [safety, compliance]` — reported **5**, with no reason written anywhere. The cheapest way to make the check quiet is to excuse everything, and nothing notices. An exclusion is therefore treated as a claim about the product and must carry a written reason in a table row naming the value. A table rather than prose because "safety" occurs in any document discussing safety, and a mention is not a justification. `-`, `TBD` and `n/a` are refused: they are an author acknowledging the question and declining to answer it. The floor is three words, on structure rather than length — a character count teaches padding.

  **The severities invert on purpose.** `unowned` is `medium`; an unjustified exclusion is `high`, because it asserts completeness with nothing behind it *and* removes the finding that would have prompted the work. A typo'd exclusion is `high` for a related reason: it excuses nothing while reading, to whoever wrote it, as handled.

  **`UNCHECKED` is not a fourth flavour of pass**, and the criterion written to forbid it caught the code that did it — the first draft printed `PASS` over a bundle whose modules declared no vocabulary at all. It fails only under `--strict`: installing quoin must not break a repository that has not adopted the vocabulary, but one asking for strict completeness is told completeness cannot be known.

  Two things had to be true before any of this could report anything, and only one was. The module had to declare the projection (iso v0.15.0, pinned in the commit before this) **and** the installed `quire` had to carry FR-059 — the local binary was **0.22.0**, five releases behind the CLI that pins quire-rs v0.33.0. Neither is visible as a failure; both present as a clean bundle.

  Reading documents at all is a compromise, recorded as one: `quire extract` takes a single `<DOC>`, so a bundle sweep is N subprocesses to answer a question about two frontmatter keys. quoin reads the `---` block and the raw body, nothing else. The real fix is upstream — if the FR-059 diagnostic classified each value as owned / excused / unowned, the reader disappears — and is filed as agent-ix/quire-rs#179. TC-206..TC-218.


* **2026-08-18** — **CR-014**: new [FR-036](./functional/FR-036-architecture-conformance.md) — **architecture conformance as a declared verification method** (agent-ix/quoin#92). A boundary stated in prose rots silently: nothing fails when it is crossed, so the document keeps asserting something that stopped being true. The catalog already carried the method; three separate breaks made it unreachable, and each is fixed here.

  **The advisor could not recommend it.** `architecture-conformance` is keyed on `[layering, module-boundary]`, and `module-boundary` was declared by the catalog and minted by nothing — half the rule was inert. The two are not merged: `layering` is directional (who may depend on whom), `module-boundary` is about the surface (what is exported, what may cross). The phrase `module boundary` **moved out of** `layering`'s pattern rather than appearing in both, because one phrase matching two characteristics is how two names stop meaning different things (CON-3).

  This turned out to be one instance of a much larger gap. A census of the shipped catalog — 33 methods, 60 distinct `characteristics` values, against the 19 `characteristicsOf` can mint — found **41 of 60 unmintable** and **7 methods unreachable outright**, `integration-testing` and `mutation-testing` among them. Filed as agent-ix/quoin#128 and deliberately not fixed here: several of the 41 are not lexical facts and need a fact source rather than a regex, and widening `characteristicsOf` to lower a count is the move this project forbids.

  **The criterion is in the failure line.** FR-034 justified finding-shaped evidence by the join between a scanner's rule id and an obligation; for SARIF that join is a mapping someone maintains, and for an audit script it is stated by the tool — `check_no_schemars: FAIL — 'schemars' present in Cargo.lock (FR-003-AC-4).` Nothing has to be kept in agreement with anything. `rulesEvaluated` counts `OK` lines too, so seven passing checks read as a result rather than as the absent scan FR-034 calls vacuous.

  **quoin's own boundaries are tests, not audit scripts** — and the first attempt got this wrong. The method's prior art is `quire-rs/scripts/audits/`, bash because a Rust repo has no import-graph linter and its checks must survive a broken build. Neither condition holds here. Written as shell, the executor check reported five violations on its first run, every one of them `LINE.exec(line)`: `RegExp.exec` read as `child_process.exec` by a regex that cannot tell them apart. **Bad rule, not bad corpus.** The compiler API can tell them apart, and the checks now run in `make test` with every other assertion about this repository. The adapter is unaffected — it reads `quire-rs`'s seven scripts, which remain right for that repository; whether five of those should be `cargo deny` bans and clippy lints is agent-ix/quire-rs#178.

  Two boundaries are declared. **Commands are leaves**, so the library loads without oclif — `tsc` accepts a cycle that only bites at runtime in whichever host loads it first. **quoin executes exactly `git`, `quire` and `ix-flow`**, which is ADR-0011 invariant 1 made mechanical: a run record's claim is *"this ran in your CI"*, true only while quoin is not the thing running it. The set is asserted whole and sorted rather than by membership, so a new binary fails by default instead of passing until someone extends a list — the failure mode `quire-rs`'s own `# extend as needed` comment demonstrates. Both checks were observed to fail against an injected violation before being relied on (CON-4). TC-197..TC-205.


* **2026-08-18** — **CR-013**: new [FR-035](./functional/FR-035-combinatorial-coverage.md) — **t-way coverage over a declared configuration space** (agent-ix/quoin#90). quire-rs FR-061 mints the obligation and states the space in the obligation's own statement; this computes what a run reached and **names what it did not**. The gap list is the deliverable: a percentage says how much is missing, the list says which combinations to run.

  A combinatorial obligation is recognised by `parseSpace(statement) !== null` — that IS the test, with no second flag to keep in agreement. A configuration exercising values the spec never declared covers nothing, because counting it would let a coverage number rise by testing something else.

  **The advisor signal is structural, not prose.** The existing `configuration-matrix` characteristic is a regex over words like "configuration" and "feature flag"; a minted space reads `2-way over features(default|python|wasm)` and matches none of them, so the obligations that most need the combinatorial method would be exactly the ones never advised for it. A statement that parses as a space is a configuration matrix by construction — and unlike a widened regex, that cannot false-positive on prose.

  TC-183 asserts quoin computes the same demanded-tuple count quire-rs does for the same space (its TC-925). Disagreement would mean an obligation is measured against a target it does not state. TC-180..191.


* **2026-08-18** — **CR-012**: new [FR-034](./functional/FR-034-finding-shaped-evidence.md) — **finding-shaped evidence** (agent-ix/quoin#115). Five of the eight formats quoin means to read emit findings rather than run outcomes, and forced into `RunEntry` **a clean semgrep run and a semgrep run that never executed are indistinguishable**. `FindingRecord` makes the distinction structural: the record is written only when an adapter read a real report envelope, so its existence is the proof of execution — `findings: []` is evidence, no record is not.

  **Vacuity is redefined for this shape rather than left silent.** For a run it is *every bound symbol skipped*; a scan has no symbols, so that is inapplicable. A scan is vacuous when it **evaluated no rules** — it reports zero findings too, and from the findings list alone the two are identical. With no rule count reported the check stays silent rather than guessing.

  **SARIF first, decided from real output** as the ticket required: SARIF is primary because semgrep, CodeQL, ESLint and ZAP converge on it, and `cargo-audit` keeps a bespoke adapter for one measured reason — it emits no SARIF at all. Its adapter is tested against `cargo audit --json` output captured from quire-rs and checked in unedited; a fixture written to match the reader only proves the reader parses itself.

  Wiring the auditor exposed a latent index misalignment: `runs` is built from the run-backed bindings, so any check indexing the full binding list would pair a binding with another suite's run the moment one binding was scan-backed. Silent until scans existed, wrong from the moment they did. TC-176 pins it. TC-165..176.


* **2026-08-18** — **CR-011**: new [FR-033](./functional/FR-033-evidence-format-adapters.md) — **evidence format adapters** (agent-ix/quoin#114). `quoin evidence record --results` parsed one hardcoded shape with no dispatch and no plugin point; it now selects an adapter by `--adapter`, else by the suite's `--tool`, else the normalized `entries` shape, which stays available so the registry is never a gate on recording evidence.

  Three decisions worth recording. **The shipped adapters name no evidence kind**: a JUnit file is emitted by unit, integration and e2e suites alike, so an adapter answering "Unit" would assert something the format does not contain — and would mint a *fourth* copy of a vocabulary that already exists in the catalog, the Test Matrix and the suite registry, in a repository where the tests holding those three honest cannot see it. **An unknown `--adapter` is an error**, never a silent fall back, because falling back parses a JUnit file as JSON and sends the reader to their XML instead of their typo. **lcov is deliberately absent**: `RunEntry.symbol` is a test symbol and coverage measures production code, with no `outcome` at all; forcing it needs either a threshold (verdict policy in the intake layer) or an invented outcome. It moves to #91b, with the reasoning recorded rather than the gap.

  `cargo-mutants` is in because it is the only format with a native `score`, and designing the contract without exercising `score` designs it blind. Its entries name production functions and bind to no obligation until a requirement→production-code relation exists (agent-ix/quire-rs#171) — the honest state, not a convenient one. TC-151..164.

* **2026-08-17** — **CR-007**: the latest run of a suite is the newest by `timestamp` (agent-ix/quoin#104). `latestRuns` and `gc` both took `listRuns(...).at(-1)` — the lexicographically last `<commit12>.json`. A commit prefix is uniformly random hex, so that picked the newest run **with probability 1/n**. The comment defending it said the store "holds no clock of its own"; `RunRecord.timestamp` had been there since FR-030 was written.

  Three checks rested on it. `stale-evidence` compares `run.commit` against HEAD, so recording a fresh run at HEAD and then auditing could report the obligation stale — and re-recording could not fix it, because the ordering is a property of the hashes rather than of anything you do. `vacuous-evidence` reads which symbols the run reported, so a symbol added in the newest run read as "absent from the run" and produced a **high**-severity finding against evidence that passed. And `gc` retained `runs.at(-1)`, so the newest run was deleted whenever its prefix sorted low and no binding named it.

  New `readRuns` / `latestRun` order by `timestamp` with the commit as tiebreak, so a tie resolves the same way on every machine. **FR-030-AC-12** and **TC-130** pin it with fixtures whose newest run's commit prefix sorts *first* — the only arrangement in which filename order and time order disagree, which is why the defect survived a suite that already covered `gc`.

Every obligation whose criticality demanded two independent methods was flagged, permanently, and no amount of recording could clear it.   FR-030 gains **AC-11** and FR-032 gains **AC-8**. Every auditor check now reads the whole group rather than one binding: a suspect link fires when **any** binding predates the current statement (a sibling that re-bound after the reword does not absolve the one that did not — that binding still claims to discharge a statement it never saw), evidence is vacuous only when **every** symbol in **every** suite was skipped or absent (one suite that genuinely ran is evidence, and calling the obligation vacuous because a second suite skipped is the false alarm that gets a check switched off), and multiplicity finally measures something real. `affirm` clears every suite's suspicion unless narrowed with `suite`, because the judgement being recorded — "I have read the new statement and the evidence still discharges it" — is about the requirement rather than about one harness.

* **2026-08-17** — **FR-032** (new FR): the **evidence auditor** — suspect links, staleness, vacuity (agent-ix/quoin#80, epic agent-ix/quire-rs#81 P1, the last ticket of the track). A trace link was a string match that never expired, and evidence rotted three ways with none of them detected: the statement changed after binding (the DOORS suspect-link idea, stolen deliberately); the binding named a missing run or one behind HEAD; every tagged symbol was skipped or never reported. **The auditor runs nothing** (ADR-0011 invariant 1) — it reads the store and reports, and that separation is what makes the report trustworthy, because an auditor that could re-run a suite could also make a finding disappear by re-running it. Four judgement calls are recorded. **Severity says what kind of wrong**: high is evidence that *claims to exist and does not hold*; medium is ordinary work in progress — an unwritten test and a lie about a written one are different problems, and grading them the same teaches readers to skim both. **Independence is measured in suites**, not symbols: two symbols in one suite share a harness, fixtures and a failure mode, so counting them as two methods would let one broken assumption look like corroboration. **A check that cannot be performed is skipped, never guessed**: without a catalog, method conformance is not asked, because an absent catalog means the question cannot be asked rather than that the answer is yes. And the auditor **stops at the first disqualifying finding per obligation**, because reporting four consequences of one cause is how a report becomes unreadable. Every check is a pure function of its inputs — no clock, no filesystem walk, no subprocess inside the audit — which is what makes the whole thing testable without a repository. **Verified end-to-end**: record → bind → reword the criterion → `[high] suspect-link` → affirm → healthy. Matrix: TC-137..TC-144. Closes agent-ix/quoin#80.

* **2026-08-17** — **FR-031** (new FR): the **catalog-driven verification-method advisor** (agent-ix/quoin#89, epic agent-ix/quire-rs#81 P1). `skills/spec-evidence-analysis` carried its own method list — `test | analysis | inspection | demonstration` plus a few evidence kinds — declared in no manifest and read by no code, and the consequence was structural rather than cosmetic: `Verification` columns defaulted to `Test` by habit, and **nothing ever advised DAST for an attack surface, monitors for a temporal property, or fault injection for a reliability NFR**. Those recommendations were not wrong, they were unreachable. Rule matching is now **code**: a method is recommended when an applicability rule matches an observed fact, ranked by how many rules agree with the method id as tiebreak, and every recommendation reports the rule and value behind it — a recommendation whose reason is not shown cannot be argued with. Three judgement calls are worth recording. **Silence is not disagreement**: a mismatch is reported only when the advisor had rules to go on, because "the author chose `Test` and we recommend nothing" is silence and flagging it would bury the real ones. **Inconclusive is an honest outcome**: where nothing matches, the advisor says so and stops — an advisor that recommends `Test` because it found nothing is the exact habit being replaced, and LLM judgement belongs on that residue only, labelled as judgement (ADR-0010). **An unobservable axis is skipped, not failed**: the engine leaves the applicability axis set open (FR-054-CON-2), so a module may declare rules this advisor has no facts for; such a rule contributes nothing rather than vetoing a method a different rule already matched. The skill was rewritten to read `quoin catalog methods` rather than recall a table, and its own method table is gone. **The ticket's claimed upstream blocker did not exist**: it said a new `analysis` enum value was needed, and `evidence` was already among the eleven. Matrix: TC-129..TC-136. Closes agent-ix/quoin#89.

* **2026-08-17** — **FR-030** (new FR): the **evidence store** — the artifact of record for what actually ran, against which statement, by which run (agent-ix/quoin#79, epic agent-ix/quire-rs#81 P1). Every quoin verification surface recomputed its view from scratch and emitted a report; nothing persisted what was checked, which is the "green matrix over dead links" failure already observed at ecosystem scale (1,014 trace tags binding to nothing while matrices read as covered). **Governing principle: store only what cannot be recomputed from spec + code at HEAD.** Run outcomes, hash-at-binding, affirmations and the ratchet baseline are facts about the past; obligations are not, and are re-derived live from quire on every read, so a stored copy could only ever disagree with the requirement it describes — TC-128 asserts no statement, document or method reaches the store. **The store lives under `spec/`**, which corrects agent-ix/quoin#79's original layout: CR-045 bounds the document walk to `<scope>/spec`, and a typed registry at the repository root minted nothing and was reported nowhere while the identical file under `spec/` was walked, validated and minted its ids. **Auto-bind, explicit affirmation**: first discharge binds without asking, because requiring a signature on something the evidence already proves puts a gate in front of the common case and teaches people to click through it; re-affirmation after a rewording is the judgement call and stays explicit — and re-running the test does **not** clear suspicion, or the state would clear itself on the next CI run and the detector would never fire. Binding happens only on a **passing** symbol, while the run is recorded whatever its outcome, because a suite that stopped passing is what a freshness check needs to see. **Verified end-to-end on a real repository**: record → bound 1 → reword the criterion → suspect. Building it surfaced two gaps closed upstream: the vendored schemas were never copied into `dist/` (every runtime read failed with ENOENT), and no module declared an `obligations:` source, so quire-rs FR-053 shipped **inert** — `quoin evidence record` bound nothing and reported every trace id as unmatched until spec-artifacts-process v0.16.0 declared them. Matrix: TC-119..TC-128. Closes agent-ix/quoin#79.

* **2026-08-17** — **FR-029** (new FR): quoin **consumes the published quire JSON contract** (agent-ix/quoin#88, epic agent-ix/quire-rs#81 P1). quoin had never parsed quire JSON in code: the `properties --json` and `coverage --json` shapes lived only as prose in skill markdown, consumed by agents reading that prose, so a shape drift surfaced as an agent confused mid-skill rather than as a diagnosable error — `spec/review.md` Finding 8, "no contract test against quire", now closed. Validation comes **before** typing, not after: TypeScript erases at runtime and JSON from a subprocess is `any`, so a type declaration alone would have caught none of this; every payload is validated against quire-rs FR-055's published schema first, and the models exist to describe what the validator has already made true. The schemas are **vendored with recorded provenance** — source tag, path, and SHA-256 — because there is no dependency edge between a Rust crate consumed by git tag and an npm package, and quoin performs no network reads on a command path; the hash is asserted every test run and `scripts/refresh-quire-schemas.mjs` refuses to copy from a checkout that is not at the pinned tag, so a copy that drifts fails immediately rather than silently teaching quoin a contract quire does not emit. The **version premise is a precondition, not an error path**: an older `quire` does not fail, it emits an older shape which a consumer misreads, so by the time a parse fails the wrong thing has already been believed. Comparison is numeric, because a lexical one ranks `0.9.0` above `0.21.0` — precisely the range this premise spans. The eval harness gained the same floor, restated rather than imported (it runs against sources, not `dist/`) with TC-117 tying the two together. Matrix: TC-110..TC-118, including TC-118 which validates a payload from the **installed** binary — the one thing a fixture cannot show. Closes agent-ix/quoin#88.
