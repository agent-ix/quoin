* **2026-08-21** — **CR-036**: a brace glob in the eval harness is a load error, not a vacuous pass (agent-ix/quoin#135). `evals/lib/assert.mjs`'s `globToRegExp` escaped `{` and `}` with the other regex metacharacters, so `**/*fuzz*.{js,ts,mjs}` compiled to a literal-suffix match no file can hit. `fileContains` fails loudly on that — "no file matched" is how CR-017 found it — but **`absentFiles` inverts the check**: nothing matches, nothing is "present", and an assertion written to prove a file was *not* created passes whether or not it was. That is the silent-no-op shape the ADR-0011 program exists to catch, inside the harness that is supposed to catch it. The fix is the ticket's smaller option: **reject rather than support** — a glob carrying `{` or `}` throws at compile, naming the glob and the remedy (one glob per alternative), because a scenario that cannot express what its author meant should fail at load, not pass at run. Brace *support* was declined deliberately: the harness's glob dialect is small because every construct it accepts is a construct every scenario reader must know it accepts. Red-verified: pre-fix, `assertExpectations` over `absentFiles: ["**/*fuzz*.{js,ts,mjs}"]` returned `ok: true` with `test/codes.fuzz.test.js` present in the fixture. The harness gains its first vitest coverage (`tests/eval-assert.test.ts`) — the eval layer's own assertion lib was verified only by running evals, which is the expensive layer to discover a harness defect in. FR-038 gains **AC-10** (the refusal ACs are the ones `absentFiles` protects). Matrix: TC-270. Exposure on `main` was already zero (swept in CR-017); this closes the trap for the next scenario author. Closes agent-ix/quoin#135.

* **2026-08-21** — **CR-035**: `RunEntry` gains a **`metric` discriminator**, and the mutation floor stops scoping by tool name (agent-ix/quoin#138). `score` is deliberately generic — *"a mutation score, a coverage percentage, a measured latency"* — and the first draft of FR-039 compared a p95 latency against a floor of 0.8. The mitigation scoped scores to runs whose `tool` led with a name from the catalog's `mutation-testing.tooling`, which had the three weaknesses the ticket names: it hardcoded a method id in the engine, it was a tool allowlist by another name (an unlisted mutation tool got `unmeasured-mutation-score` while holding a real score), and it did not generalize. The measurement is now **named where it is recorded**: the `cargo-mutants` adapter — which knows it produces a mutation score and nothing else — writes `metric: "mutation-score"` (one exported constant, `MUTATION_SCORE_METRIC`, shared by writer and reader so the spellings cannot drift), and `scoresFor` filters on the entry's `metric` alone. The catalog leaves the check entirely: `mutationToolsIn`/`toolsFor` are deleted, `scoresFor(bindings, runs)` drops its catalog parameter at both call sites (auditor and advisor), and the no-catalog-silence rule is gone with the guessing it guarded — TC-239 is retired in place, TC-269 states the replacement. **Migration is migration, not dual-read**: an entry without a `metric` is not a mutation score even when its tool string says `cargo-mutants`; the remedy is re-recording through the adapter. In-tree fixtures migrated: `tests/auditor.test.ts` (TC-219's scored fixtures, the mutationCatalog fixture deleted) and `tests/evidence-adapters.test.ts` (the Timeout deep-equal, plus new assertions that the label survives parse and the end-to-end record path). Matrix: TC-269; TC-219, TC-239 updated.

* **2026-08-21** — **CR-028**: the `quire` subprocess gets a `maxBuffer` sized for real corpora, and a killed child stops being blamed on its own stderr (agent-ix/quoin#164, epic #172 P0). No call site set `maxBuffer`, so Node's 1 MiB default applied — and filament-ide-rs (268 spec files, 1,107 obligations) emits **1,090,714 bytes** of `coverage --json`, 4% over. Six commands died: `assurance`, `advise`, and `evidence audit`/`record`/`affirm`/`baseline`. A child that never exited is now reported by its cause — `err.code`/`err.signal`, which were both available and neither read — with no exit status and no stderr appended. The child's stderr is the diagnosis only when the child itself exited non-zero (AC-10's case, previously verified by inspection only and now pinned by a test). FR-029 gains **AC-11** and **AC-12**; the throwing path, which no test had ever exercised, gains four via a fake `quire` first on PATH — the fake-ix-flow pattern, because TC-203's architecture check requires the executed binary to stay a string literal. * **2026-08-19** — **CR-026**: the advisor **reads the evidence store**, and `concolic-execution` becomes reachable — the last catalog method no requirement could elicit (agent-ix/quoin#158; CR-025 took that count from 7 of 33 to 1, this takes it to **0**). It was keyed on `path-sensitive` and `hard-to-reach-branch`, both properties of the *implementation's* control flow, which no specification states.

  **Nobody reaches for concolic execution up front** — it path-explodes and it is slow. The industrial pattern is hybrid fuzzing: fuzz until the coverage curve flattens, hand the stuck branches to a solver, feed the solved inputs back as seeds (Driller 2016, then QSYM, SymCC, Fuzzolic). So three triggers are stated and two are observed. Stated: `magic-value-comparison` (a checksum, CRC or HMAC — the wall a fuzzer cannot climb), `secret-dependent-branch` and `reference-equivalence`. Observed: `fault-detection-unmeasured` (the obligation is exercised and nothing measures whether the exercise discriminates) and `fault-detection-failed` (something measured it and a seeded fault survived). `high-criticality`, already minted, carries the standards-driven case — DO-178C Level A MC/DC and its ISO 26262 / IEC 62304 equivalents.

  **`advise` still performs no I/O.** The command opens the store and hands the answer in, the same way `propertyShape` and `archetype` arrive. `scoresFor` is the auditor's, reused rather than reimplemented, so the auditor's finding and the advisor's recommendation cannot disagree about the same run. `latestRuns`/`latestScans` moved from a command's privates into the store beside `readBindings` — their being private *and uncalled* is what SR-005 FND-002 was.

The count is not the argument; the argument is that the trigger separated nothing. Found by running the advisor over a real corpus, one module release after reading the entry had not shown it.

  **Two stale pins were the real consumer gap.** `default-modules.yaml` pinned `spec-artifacts-process` at **v0.19.0** and `spec-artifacts-iso` at **v0.16.0**, so quoin had been consuming a catalog two releases old — including missing the `implements` marker forms shipped in process v0.20.0 earlier the same day. Bumped to **v0.21.1** and **v0.17.0**.

Nothing records coverage over time, and a proxy invented to stand in for it is the CR-014 failure. **And still unsayable:** that concolic is an escalation. * **2026-08-19** — **CR-024**: quoin's own matrix rows **bind to the tests that back them** (agent-ix/quoin#124). **What the number counts:** rows in `spec/matrix.md` marked ✅ that `quire coverage --scope .` cannot confirm, because no symbol carries their id — quire calls these *status lies*. **48 before, 0 after**; rows the engine confirms as backed went **216 → 266** of 579.

  The cause was one convention, uniformly applied and uniformly dead: `describe("TC-nnn …")`. **`describe(…)` registers no symbol at all** — the TypeScript extractor treats it as a grouping construct and only `it(…)`/`test(…)` become bindable symbols — so an id in a describe title names nothing however carefully it was written. The tests were always real; 448 of them pass. It was the binding that did not exist.

  **Fixed by unifying on the form that binds, not by teaching the engine a second spelling.** quire-rs's `TraceTagGrammar` can model a trace-embedding test name, and declaring one would have bound the corpus without touching a file — but this repo's own standing rule is that a rule accepting every spelling enforces nothing, so 47 tags moved onto the registrations instead.

  Two rows were not a tagging problem and are worth separating. **TC-146** ("kind-to-kind conformance; `unknown-method` reported") was tested under TC-142's describe — real coverage, wrong id. **TC-148** (`--module` supplies the audit catalog) had **no test at all** and read ✅ on the strength of its `Static` verification type; this repo deliberately does not exempt `Static` from status lies, precisely so an overclaim like that surfaces. It now has both halves: a behavioural test that `loadMethodCatalog([root])` returns a method the installed roots do not carry, and a source assertion that the command hands the loader `flags.module` — the wiring no other test in the file would catch.

  **One row exposed an engine gap and was worked around, not papered over.** TC-118 used vitest's curried `it.skipIf(cond)("title", …)`, whose title sits on a line the line-based extractor never reads, so the registration produced no symbol. Rewritten to `it("title", (ctx) => …)` with `ctx.skip()`. Filed upstream rather than absorbed: a repo using the modifier forms gets silent zero coverage with no diagnostic.

* **2026-08-19** — **CR-023**: a run binds through an obligation's declared **test cases**, not only its own id (FR-030-AC-15, TC-245). Closes agent-ix/quoin#144.

  A tool reports the id it knows. A unit test carries the criterion's own id because the tag is written in the test; an **agent-eval report — and any tool keyed on the Test Matrix — carries the test-case id**. Both are stated by the same criteria row, `Eval (TC-EV-057)`, and quire-rs FR-053-AC-11 (v0.35.0) now carries that join on the obligation, so the store resolves it rather than re-parsing the criteria table — the duplication FR-050 exists to prevent.

  Before this, `quoin evidence record --adapter agent-eval` reported `bound: 0` and `unmatched trace ids … TC-EV-057` while the join sat in the FR's own table. 71 matrix rows across `spec/evals.md`, FR-028 and FR-038 were unbacked for want of it.

  Two rules the tests pin rather than leave implied. **A direct obligation id wins**: if a criterion's cell named a sibling criterion's id, the indirect route would report a discharge nobody stated directly. **A test case discharging several criteria binds all of them**, because the row says each is verified by that test case and binding only the first leaves the rest undischarged with the evidence sitting right there.

* **2026-08-19** — **CR-021**: new [FR-042](./functional/FR-042-agent-eval-evidence.md) — **agent-eval reports as run evidence**, closing the first half of `SR-008` FND-001 (agent-ix/quoin#142).

The store matches trace ids against **obligation** ids — a junit test carries `FR-001-AC-1` in its own name, so that works — while an eval report carries the **scenario** id, `TC-EV-057`, which is a Test Case row. FND-002 — that `Eval` is not a declared verification method at all — is module data and stays open under #142.

The baseline is now a flat set of `<kind>:<obligation>` keys. No migration: nothing ever wrote one, because **`writeBaseline` had no command** — `--ratchet` read a file no verb produced. **`quoin evidence baseline`** writes it, and its doc says plainly what re-running it means.

  Also removed: the hardcoded `multiplicityRequires: ["P0"]`. No obligation source in the ecosystem declares a `criticality_column` (2,304 of 2,304 `Acceptance Criteria` tables carry no priority — spec-artifacts-process CR-005), so it was a rule that could never fire and would have fired on *everything* the moment a column appeared. It is now `--multiplicity-requires`, unset by default. Matrix: TC-146, TC-147, TC-148.

* **2026-08-17** — **CR-007**: the latest run of a suite is the newest by `timestamp` (agent-ix/quoin#104). `latestRuns` and `gc` both took `listRuns(...).at(-1)` — the lexicographically last `<commit12>.json`. A commit prefix is uniformly random hex, so that picked the newest run **with probability 1/n**. The comment defending it said the store "holds no clock of its own"; `RunRecord.timestamp` had been there since FR-030 was written.

  Three checks rested on it. `stale-evidence` compares `run.commit` against HEAD, so recording a fresh run at HEAD and then auditing could report the obligation stale — and re-recording could not fix it, because the ordering is a property of the hashes rather than of anything you do. `vacuous-evidence` reads which symbols the run reported, so a symbol added in the newest run read as "absent from the run" and produced a **high**-severity finding against evidence that passed. And `gc` retained `runs.at(-1)`, so the newest run was deleted whenever its prefix sorted low and no binding named it.

  New `readRuns` / `latestRun` order by `timestamp` with the commit as tiebreak, so a tie resolves the same way on every machine. **FR-030-AC-12** and **TC-130** pin it with fixtures whose newest run's commit prefix sorts *first* — the only arrangement in which filename order and time order disagree, which is why the defect survived a suite that already covered `gc`.

* **2026-08-17** — **CR-006**: a binding is keyed on `(obligation, suite)` (agent-ix/quoin#102), and the auditor folds over the group. `BindingsFile`'s own doc says the graph *is* cross-suite — "one obligation can be discharged by a unit test and a benchmark, and splitting the file per suite would make that relationship something to reassemble" — and `bind()` searched by obligation id alone, so the second suite's discharge **overwrote** the first. The relationship the file exists to hold was destroyed on write, silently.

  The consequence nobody could have hit by hand: `insufficient-multiplicity` counted the distinct suites bound to an obligation and required two, over a set no code path could ever grow past one. Every obligation whose criticality demanded two independent methods was flagged, permanently, and no amount of recording could clear it. The finding was invisible only because criticality is `null` for all 583 obligations the ecosystem derives (spec-artifacts-process CR-005) — it was one populated column away from firing on everything.

  FR-030 gains **AC-11** and FR-032 gains **AC-8**. Every auditor check now reads the whole group rather than one binding: a suspect link fires when **any** binding predates the current statement (a sibling that re-bound after the reword does not absolve the one that did not — that binding still claims to discharge a statement it never saw), evidence is vacuous only when **every** symbol in **every** suite was skipped or absent (one suite that genuinely ran is evidence, and calling the obligation vacuous because a second suite skipped is the false alarm that gets a check switched off), and multiplicity finally measures something real. `affirm` clears every suite's suspicion unless narrowed with `suite`, because the judgement being recorded — "I have read the new statement and the evidence still discharges it" — is about the requirement rather than about one harness.

  Ordering moved off `localeCompare` in the store, the auditor and the record path in the same pass: `bindings.json` is checked in and its diff is meant to *be* the per-PR delta, and `localeCompare` without an explicit locale depends on the runtime's ICU data, so two machines could serialize one binding set two ways. Matrix: TC-129, TC-145.

* **2026-08-17** — **FR-032** (new FR): the **evidence auditor** — suspect links, staleness, vacuity (agent-ix/quoin#80, epic agent-ix/quire-rs#81 P1, the last ticket of the track). A trace link was a string match that never expired, and evidence rotted three ways with none of them detected: the statement changed after binding (the DOORS suspect-link idea, stolen deliberately); the binding named a missing run or one behind HEAD; every tagged symbol was skipped or never reported. **The auditor runs nothing** (ADR-0011 invariant 1) — it reads the store and reports, and that separation is what makes the report trustworthy, because an auditor that could re-run a suite could also make a finding disappear by re-running it. Four judgement calls are recorded. **Severity says what kind of wrong**: high is evidence that *claims to exist and does not hold*; medium is ordinary work in progress — an unwritten test and a lie about a written one are different problems, and grading them the same teaches readers to skim both. **Independence is measured in suites**, not symbols: two symbols in one suite share a harness, fixtures and a failure mode, so counting them as two methods would let one broken assumption look like corroboration. **A check that cannot be performed is skipped, never guessed**: without a catalog, method conformance is not asked, because an absent catalog means the question cannot be asked rather than that the answer is yes. And the auditor **stops at the first disqualifying finding per obligation**, because reporting four consequences of one cause is how a report becomes unreadable. Every check is a pure function of its inputs — no clock, no filesystem walk, no subprocess inside the audit — which is what makes the whole thing testable without a repository. **Verified end-to-end**: record → bind → reword the criterion → `[high] suspect-link` → affirm → healthy. Matrix: TC-137..TC-144. Closes agent-ix/quoin#80.

* **2026-08-17** — **FR-031** (new FR): the **catalog-driven verification-method advisor** (agent-ix/quoin#89, epic agent-ix/quire-rs#81 P1). `skills/spec-evidence-analysis` carried its own method list — `test | analysis | inspection | demonstration` plus a few evidence kinds — declared in no manifest and read by no code, and the consequence was structural rather than cosmetic: `Verification` columns defaulted to `Test` by habit, and **nothing ever advised DAST for an attack surface, monitors for a temporal property, or fault injection for a reliability NFR**. Those recommendations were not wrong, they were unreachable. Rule matching is now **code**: a method is recommended when an applicability rule matches an observed fact, ranked by how many rules agree with the method id as tiebreak, and every recommendation reports the rule and value behind it — a recommendation whose reason is not shown cannot be argued with. Three judgement calls are worth recording. **Silence is not disagreement**: a mismatch is reported only when the advisor had rules to go on, because "the author chose `Test` and we recommend nothing" is silence and flagging it would bury the real ones. **Inconclusive is an honest outcome**: where nothing matches, the advisor says so and stops — an advisor that recommends `Test` because it found nothing is the exact habit being replaced, and LLM judgement belongs on that residue only, labelled as judgement (ADR-0010). **An unobservable axis is skipped, not failed**: the engine leaves the applicability axis set open (FR-054-CON-2), so a module may declare rules this advisor has no facts for; such a rule contributes nothing rather than vetoing a method a different rule already matched. The skill was rewritten to read `quoin catalog methods` rather than recall a table, and its own method table is gone. **The ticket's claimed upstream blocker did not exist**: it said a new `analysis` enum value was needed, and `evidence` was already among the eleven. Matrix: TC-129..TC-136. Closes agent-ix/quoin#89.

* **2026-08-17** — **FR-030** (new FR): the **evidence store** — the artifact of record for what actually ran, against which statement, by which run (agent-ix/quoin#79, epic agent-ix/quire-rs#81 P1). Every quoin verification surface recomputed its view from scratch and emitted a report; nothing persisted what was checked, which is the "green matrix over dead links" failure already observed at ecosystem scale (1,014 trace tags binding to nothing while matrices read as covered). **Governing principle: store only what cannot be recomputed from spec + code at HEAD.** Run outcomes, hash-at-binding, affirmations and the ratchet baseline are facts about the past; obligations are not, and are re-derived live from quire on every read, so a stored copy could only ever disagree with the requirement it describes — TC-128 asserts no statement, document or method reaches the store. **The store lives under `spec/`**, which corrects agent-ix/quoin#79's original layout: CR-045 bounds the document walk to `<scope>/spec`, and a typed registry at the repository root minted nothing and was reported nowhere while the identical file under `spec/` was walked, validated and minted its ids. **Auto-bind, explicit affirmation**: first discharge binds without asking, because requiring a signature on something the evidence already proves puts a gate in front of the common case and teaches people to click through it; re-affirmation after a rewording is the judgement call and stays explicit — and re-running the test does **not** clear suspicion, or the state would clear itself on the next CI run and the detector would never fire. Binding happens only on a **passing** symbol, while the run is recorded whatever its outcome, because a suite that stopped passing is what a freshness check needs to see. **Verified end-to-end on a real repository**: record → bound 1 → reword the criterion → suspect. Building it surfaced two gaps closed upstream: the vendored schemas were never copied into `dist/` (every runtime read failed with ENOENT), and no module declared an `obligations:` source, so quire-rs FR-053 shipped **inert** — `quoin evidence record` bound nothing and reported every trace id as unmatched until spec-artifacts-process v0.16.0 declared them. Matrix: TC-119..TC-128. Closes agent-ix/quoin#79.

* **2026-08-17** — **FR-029** (new FR): quoin **consumes the published quire JSON contract** (agent-ix/quoin#88, epic agent-ix/quire-rs#81 P1). quoin had never parsed quire JSON in code: the `properties --json` and `coverage --json` shapes lived only as prose in skill markdown, consumed by agents reading that prose, so a shape drift surfaced as an agent confused mid-skill rather than as a diagnosable error — `spec/review.md` Finding 8, "no contract test against quire", now closed. Validation comes **before** typing, not after: TypeScript erases at runtime and JSON from a subprocess is `any`, so a type declaration alone would have caught none of this; every payload is validated against quire-rs FR-055's published schema first, and the models exist to describe what the validator has already made true. The schemas are **vendored with recorded provenance** — source tag, path, and SHA-256 — because there is no dependency edge between a Rust crate consumed by git tag and an npm package, and quoin performs no network reads on a command path; the hash is asserted every test run and `scripts/refresh-quire-schemas.mjs` refuses to copy from a checkout that is not at the pinned tag, so a copy that drifts fails immediately rather than silently teaching quoin a contract quire does not emit. The **version premise is a precondition, not an error path**: an older `quire` does not fail, it emits an older shape which a consumer misreads, so by the time a parse fails the wrong thing has already been believed. Comparison is numeric, because a lexical one ranks `0.9.0` above `0.21.0` — precisely the range this premise spans. The eval harness gained the same floor, restated rather than imported (it runs against sources, not `dist/`) with TC-117 tying the two together. Matrix: TC-110..TC-118, including TC-118 which validates a payload from the **installed** binary — the one thing a fixture cannot show. Closes agent-ix/quoin#88.
