# FR-197: The dossier SOUP list renders the source report without a new disposition

## Description

When `quoin dossier generate` selects `soup` (document id `DOS-SOUP`), the SOUP
list SHALL render the rows and status words of `quoin soup report` as that
source gives them.

## Inputs

- `quoin soup report --repo <dir> --binding <file> --as-of <instant> --json`,
  optionally with `--records <dir>` and `--support <file>`
  ([FR-144](./FR-144-soup-report.md)). Its builder currently lives in
  `rust/crates/quoin-cli/src/soup/report.rs`; the dossier and CLI SHALL call
  one shared builder, moved to a library crate before the generator is added.
- The dossier passes the source selection inputs through. It does not read an
  SBOM as an alternate SOUP source.

## Outputs

- `dossier/DOS-SOUP.md`, carrying the supplied `as_of` in frontmatter and
  `As of:` in the body, a table of source rows in source order, the source's
  unmatched findings and scan states, and the final `## Gaps` section.
- Each row states component identity, version, served requirements, known
  anomalies, advisory and policy findings with person-authored dispositions,
  support status and end-of-support date as FR-144 reports them.

## Behavior

- The SOUP list SHALL preserve the source row order: unresolved advisory or
  policy rows first, past-end-of-support rows next, then the remaining rows.
- The SOUP list SHALL copy the source's advisory, policy, support and VEX
  status words verbatim; it SHALL NOT convert an unresolved finding into an
  `allowed` or `free of advisories` claim.
- An unresolved advisory or policy finding SHALL produce a
  `soup_unresolved_advisory` gap naming its component and finding.
- A source row marked past end of support SHALL produce a
  `soup_past_end_of_support` gap naming the component.
- Each source field the report says is `not stated` or `unknown` SHALL retain
  that text and produce `soup_field_not_stated` naming the component and field
  when it is required for the dossier row.
- If `--binding` is absent, the source SHALL refuse the request.
- When the source refuses an absent binding, the dossier SHALL surface exit 3
  naming `quoin soup report` and write no file.
- The SOUP list SHALL NOT derive a support date, advisory disposition or
  risk ranking from another value, nor read an SBOM file.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-197-AC-1 | For a fixture with three FR-144 rows in three priority groups, the dossier has exactly those rows in the source order and copies every status word. | Test |
| FR-197-AC-2 | A row whose `serves` field is absent displays `not stated` and produces `soup_field_not_stated` naming that field and component. | Test |
| FR-197-AC-3 | An unresolved advisory and an unresolved policy finding each stay unresolved in the document and each produces `soup_unresolved_advisory`; no row says `allowed`. | Test |
| FR-197-AC-4 | A past-end-of-support row produces `soup_past_end_of_support`; an unknown support status stays `unknown` and does not acquire a date. | Test |
| FR-197-AC-5 | With no `--binding`, the dossier exits 3, names `quoin soup report`, and writes no file; with no `--as-of`, the command refuses the usage before writing. | Test |
| FR-197-AC-6 | Removing the SBOM file from the fixture does not change the generated bytes; two runs with the same `--as-of` are byte-identical. | Test |
| FR-197-AC-7 | The dossier and `quoin soup report --json` use the same library builder; a source row added by that builder appears once in each output. | Inspection |
