# FR-188: quoin dossier generates, checks and exports the selected dossier documents

## Description

Quoin SHALL provide `quoin dossier generate`, which writes the selected dossier documents from the repository's records.

Quoin SHALL provide `quoin dossier check`, which compares the selected dossier documents with the files on disk and writes nothing.

Quoin SHALL provide `quoin dossier export`, which exports the selected, committed and current dossier documents through `quire export`.

The documents are SRS (`srs`, id `DOS-SRS`), architecture (`architecture`, id `DOS-ARCH`), trace matrix (`trace-matrix`, id `DOS-TRACE`) and requirements mapping matrix (`rmm`, id `DOS-RMM`).

## Inputs

- `generate [--doc srs|architecture|trace-matrix|rmm]... [--out <DIR>] [--scope <DIR>] [--module <PATH>]... [--clause-binding <PATH>]... [--pack <PACK>] [--as-of <ISO-8601>] --version <TEXT> [--json]`.
- `check` takes the same selectors as `generate`.
- `export --to pdf|docx --output <PATH>` takes the same selectors as `generate`, and also `[--release <TAG>] [--approval <PATH>]... [--template <PATH>] [--quire <PATH>]`.

## Outputs

- `generate`: one Markdown file per selected document at `<DIR>/<document-id>.md`. `<DIR>` is `dossier` unless `--out` names another. With no `--doc` all four documents are selected.
- `check`: per document, `matches` or `differs`.
- `export`: the file `quire export` writes.
- With `--json`: `{documents:[{id, kind, path, status, gaps:[{gap_kind, subject, detail}]}]}` where `status` is `complete` or `incomplete`. `check` and `export` add `comparison` (`matches` or `differs`) to each document. On exit 3 the report holds `source_failure:{source, detail}`. On exit 4 the report holds `quire:{exit_code, stderr}`.

## Behavior

### Commit then export

- `generate` SHALL write Markdown into the repository.
- `generate` SHALL NOT call `quire export`.
- `export` SHALL run `quire export` as an external process with `--source-rev HEAD`.
- `export` SHALL pass `--release`, `--approval` and `--template` to `quire export` unchanged.
- When `export` selects more than one document, `export` SHALL run `quire export` once, as one bundle, with the files in the fixed order `DOS-SRS`, `DOS-ARCH`, `DOS-TRACE`, `DOS-RMM` and with `--bundle-title "Submission Dossier"` and `--bundle-id DOS`.
- When `export` selects one document, `export` SHALL run `quire export` once with that file and without `--bundle-title` and `--bundle-id`.
- The flow is commit-then-export because `quire export` takes identity and content from the blob committed at `--source-rev` and refuses a working file that differs from that commit (quire-cli FR-034 section A), and refuses identity options on JSON input. A bundle requires at least two inputs (quire-cli FR-039-AC-7), which is why one document is exported without bundle arguments.
- Quoin SHALL NOT export an uncommitted file.
- Quoin SHALL NOT render a document itself.
- Quoin SHALL NOT bypass `quire export`.

### Export currency

- `export` SHALL resolve each selected document at `<DIR>/<document-id>.md`, where `<DIR>` is `dossier` unless `--out` names another.
- `export` SHALL regenerate each selected document in memory and compare its bytes with the file at its path before it starts `quire export`.
- If a selected file is missing or its bytes differ from the regenerated bytes, `export` SHALL exit 1, SHALL name the document, and SHALL NOT start `quire export`.
- `export` SHALL NOT refuse a document because it is `incomplete`; the `Gaps` section travels with the document.

### Selection and check

- If a `--doc` value is outside the four names, the command SHALL exit 2 and SHALL write nothing.
- `generate`, `check` and `export` SHALL require `--version`, because the version is part of the generated bytes and `quire export` needs a Version or a Release (quire-cli FR-034). Without it the command SHALL exit 2 and SHALL write nothing.
- `check` SHALL regenerate each selected document in memory and compare its bytes with the file at its path.
- `check` SHALL write nothing.
- `check` SHALL count a missing file as `differs`.

### Sources and failure

- A source is one of the record readers named in FR-189 to FR-192: `requirements`, `design-join`, `design-matrix`, `systems-records`, `matrix` and `discharge`. A source is either a library operation of the Quoin workspace or the equivalent Quoin command, and gives the same result as that command.
- `generate`, `check` and `export` SHALL compute every selected document in memory before they write or compare anything.
- If a source fails, the command SHALL exit 3, SHALL name the failed source and its error in `source_failure`, and SHALL write nothing.
- If `generate` exits 2 or 3, `generate` SHALL leave every existing file under `<DIR>` unmodified.
- `generate` SHALL check before writing that `<DIR>` can be created, and SHALL exit 2 if it cannot.

### Ordering

- Quoin SHALL compare ids in dossier order: an id is split at `-` into segments; two segments of ASCII digits compare by numeric value, any other two segments compare by byte value, a digit segment sorts before a non-digit segment, and an id that is a prefix of another sorts first. `FR-99` sorts before `FR-100`, and `FR-100-AC-2` before `FR-100-AC-10`.
- Quoin SHALL sort gaps by the key (requirement id, criterion id, element id, clause id, gap kind position), where an absent id sorts first and the gap kind position is the position of the kind in the closed list below.
- A gap that names a part uses the part id as its element id.
- A gap with no id (`no_requirements`, `design_relations_unavailable`, `no_clause_binding`) sorts before gaps that name an id.

### Document set

- The generated files SHALL carry the frontmatter of the `DossierDocument` archetype that spec-artifacts-process defines for this feature: `id`, `title`, `version`, `type: DossierDocument`, `document_kind`, `generated_by: quoin dossier` and, for the RMM, `as_of`.
- Each file SHALL end with the level-2 `Gaps` section below.

### Gaps section

- Each missing input SHALL be one bullet under the final level-2 heading `Gaps`, written `` `<gap_kind>` <subject>: <detail> ``.
- The section SHALL read `Gaps: none` when it holds no gap.
- The closed list of `gap_kind` values is, in this order: `no_requirements`, `no_acceptance_criteria`, `criticality_unassigned`, `design_relations_unavailable`, `no_design_element`, `dangling_design_reference`, `design_kind_mismatch`, `no_allocation`, `unbacked_criterion`, `no_evidence`, `no_clause_binding`, `clause_open`.
- A gap SHALL name one subject: a requirement for `no_requirements`, `no_acceptance_criteria`, `criticality_unassigned` and `no_design_element`; a criterion for `unbacked_criterion` and `no_evidence`; a design reference or element for `dangling_design_reference`, `design_kind_mismatch` and `no_allocation`; a clause for `clause_open`; the document for `design_relations_unavailable` and `no_clause_binding`.
- A document with at least one gap SHALL have status `incomplete`.
- The `--json` report SHALL hold the same gaps as the Markdown, in the same order.
- Quoin SHALL report a gap and SHALL NOT drop or default it.

### Exit status

| Code | Meaning |
|------|---------|
| 0 | Every selected document is complete (and, for `check`, matches; for `export`, `quire export` succeeded). |
| 1 | Documents were generated but at least one is incomplete, or `check` found a difference, or `export` found a missing or stale file. |
| 2 | Usage error or invalid input, including a missing `--version` and a missing `--as-of` (FR-192). |
| 3 | A source failed; the report names it. |
| 4 | `quire export` failed or could not start; its exit code and stderr are passed through, and a missing executable names the path. |

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-188-AC-1 | `generate --doc srs --doc rmm` writes exactly two files and no other | Test |
| FR-188-AC-2 | `generate` with no `--doc` writes the four files at `dossier/<document-id>.md` | Test |
| FR-188-AC-3 | `generate --doc nope` exits 2 and writes no file | Test |
| FR-188-AC-4 | On a fixture whose documents are all complete, `check` on a committed file with one hand-edited line reports that document as `differs` and exits 1; with no edit it reports `matches` and exits 0 | Test |
| FR-188-AC-5 | `check` writes no file and a deleted file reports `differs` | Test |
| FR-188-AC-6 | `export --quire <missing path>` exits 4 and the report names that path | Test |
| FR-188-AC-7 | `export` over a current generated file that is not committed surfaces `quire export`'s refusal with its exit code on stderr and leaves no output file | Test |
| FR-188-AC-8 | `export` of two or more documents invokes `quire export` once with the committed files in the order `DOS-SRS`, `DOS-ARCH`, `DOS-TRACE`, `DOS-RMM` regardless of `--doc` order, `--source-rev HEAD`, `--bundle-title "Submission Dossier"`, `--bundle-id DOS`, and `--approval`, `--template` and `--release` unchanged | Test |
| FR-188-AC-9 | `export --doc srs` invokes `quire export` once with that one file and with neither `--bundle-title` nor `--bundle-id` | Test |
| FR-188-AC-10 | A dossier generated with `--out other` is exported by `export --out other`, and `export` without `--out` looks under `dossier` and exits 1 naming the missing document | Test |
| FR-188-AC-11 | `export` over a committed file that differs from the regenerated bytes exits 1, names the document and never starts `quire export` | Test |
| FR-188-AC-12 | A source that fails makes `generate` exit 3, the report names that source in `source_failure`, no file is written for any selected document, and a file that existed before the run is unchanged | Test |
| FR-188-AC-13 | `generate`, `check` and `export` without `--version` exit 2 and write nothing | Test |
| FR-188-AC-14 | A fixture with two gaps of different kinds gives a `Gaps` section with two bullets in gap order, the same two entries in the same order in `--json`, and `Gaps: none` for a complete document | Test |
| FR-188-AC-15 | A fixture with requirements `FR-99` and `FR-100` and criteria `FR-100-AC-2` and `FR-100-AC-10` lists them in dossier order, and a document-level gap sorts before a gap that names a requirement | Test |
| FR-188-AC-16 | `export` of an `incomplete` document that is committed and current runs `quire export` and does not refuse it | Test |
| FR-188-AC-17 | `generate --out <path that cannot be created>` exits 2 and writes nothing | Test |
