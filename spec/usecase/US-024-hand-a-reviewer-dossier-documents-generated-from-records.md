# US-024: Hand a reviewer dossier documents generated from the repository's records

## Story

**As a** team that must hand a reviewer a submission dossier
**I want** one command that writes the selected dossier documents from the records the toolchain already holds, lists what is missing, and sends the committed result to `quire export`
**So that** the reviewer reads documents that match the repository at one commit, and nobody retypes or invents a value to fill a gap.

## Context

The M1 documents restate requirement documents, the design join,
`quoin matrix` and `quoin discharge --rmm`. The M2 documents restate
verification, SOUP, anomaly, risk, policy, release-snapshot and EA release
verification outputs. Each source remains authoritative for its own values.
Written by hand they drift from those records. `quire export` renders a
document from a committed blob (quire-cli FR-034), so the generated Markdown is
committed before it is exported.

## Acceptance Examples (Illustrative)

### US-024-EX-1: Generate the M1 documents

- **Given** a repository with requirements, design relations and a clause binding `binding.json`, with only M1 generators registered
- **When** the team runs `quoin dossier generate --version 1.0 --clause-binding binding.json --as-of <RFC 3339 timestamp>`
- **Then** four Markdown files appear under `dossier/`, each ending in a `Gaps` section

### US-024-EX-2: A missing input is a gap, not a guess

- **Given** a requirement whose frontmatter states no criticality
- **When** the SRS is generated
- **Then** the requirement shows `unassigned` and the document lists a `criticality_unassigned` gap

### US-024-EX-3: Export follows the commit

- **Given** the generated files are reviewed and committed
- **When** the team runs `quoin dossier export --to pdf --output dossier.pdf --version 1.0 --clause-binding binding.json --as-of <RFC 3339 timestamp>` with the same values as the generation
- **Then** `quoin dossier` confirms the committed files equal the current generated bytes, and `quire export` renders the committed blobs as one bundle titled `Submission Dossier` with id `DOS`

### US-024-EX-4: Generate an M2 document with a missing input

- **Given** a repository with an authored acceptability policy and no plan record
- **When** the team selects `risk-management-plan`
- **Then** the policy is rendered, `no_plan_record` is listed as a gap, and no plan scope or responsibility is invented

### US-024-EX-5: Generate the missing M3 product documents

- **Given** a repository with authored software, device, design, and documentation-level decision records
- **When** the team selects `software-description`, `documentation-level-decision`, `software-design-specification`, or `device-description`
- **Then** each generated document names the stable ids and types of its source records, identifies the producing Quoin version, reports missing source facts as gaps, and leaves all decisions to the person-authored records

## Constraints (Contextual)

Quoin renders nothing. Rendering, templates and approval blocks belong to `quire export`.

## Dependencies (Contextual)

Upstream: StR-010 and the declared source reports. Downstream: FR-191 to
FR-201, FR-229 to FR-232, NFR-040 and NFR-041.

## Priority and Risk (Informative)

Priority is P1 for the regulated-software line. The risk is a generator that
fills a gap with a plausible value, which NFR-040 forbids.
